# 第三MVP: 単音メロディからのコード推定

一本指でメロディを弾き、直近4拍の音に合う候補コードを選びます。
正解コードを特定する機能ではなく、C major内の候補に制限した安定性重視の試作です。
既存の固定進行 `play`、コード入力 `follow`、UNO Qの機能は維持しています。

## 起動

```powershell
Set-Location D:\GitProjects\Music\auto_accompaniment
.\.venv\Scripts\python.exe -m autoaccomp.main ports
.\.venv\Scripts\python.exe -m autoaccomp.main melody-follow --input "MIDIFlex4 1" --output "Microsoft GS Wavetable Synth 0" --key C --debug-harmony
```

依存のインストールは従来と同じ `python -m pip install -r requirements.txt`。
今回の検証時、MIDIFlex物理ポート1の名前が従来の `MIDIFlex4 0` から `MIDIFlex4 1` に
変わっていました。接続順で番号が変わるため、必ず `ports` の実際の名前を使用してください。
`--key C` は省略可能。今回はC majorだけを受け付け、自動キー推定・転調は行いません。
停止はCtrl+C。既定テンポ120 BPM、4/4。`--tempo 100`、`--bars 16`、
`--no-bass`、`--no-comping` も使えます。有限小節数は起動時から計測します。
入力メロディはch1へ即時転送し、コード伴奏ch2、ベースch3と同時に鳴らします。

## 推定ルール

- 履歴は直近4拍（120 BPMで2秒）、最大256ノート。各音のMIDI番号・ピッチクラス・
  velocity・入力チャンネル・発音時刻・開始拍・離鍵時刻・終了拍・durationを保持します。
- Note Offまたはvelocity=0でdurationを確定。保持中は現在時刻までの長さを使います。
  次のNote Onは解析上だけ前の音を終了させます。入力スルー音は加工しません。
  ペダルは転送しますが、解析上の音価は物理キーのNote Offまでです。
- 候補はC / Dm / Em / F / G / Am。コードトーン3点、その他のC majorスケール音0.5点、
  スケール外音-1点を、長さと新しさで重み付けした平均点として算出します。
- 強拍（1・3拍目の前後0.2拍）は重み1.5倍。短い経過音の影響を小さくします。
- 現コードに0.20点、C→F / C→G / Dm→G / G→C / Am→Dmに0.15点を加えます。
- 最低2拍は同じコードを維持し、新候補が現コードより0.35点を超えて高いときだけ変更します。
- 採点と反映は4分音符の境界で行います。直前までの履歴を使うため、
  拍の直後に入力した音は次の拍の推定に入ります。伴奏の途中変更はしません。
- 同点は候補順で決めます。最初の1音だけでは曖昧なため、意図と異なるコードも選びます。
  複数音の履歴が蓄積するにつれて推定を更新します。
- 入力がない状態では伴奏を始めません。休符で履歴が空になった場合やスケール外音のみの
  履歴になった場合は、最後のコードを保持して伴奏を継続します。停止はCtrl+Cです。

通常は `Estimated chord` と `Active accompaniment chord` を変更時だけ表示します。
`--debug-harmony` では毎拍、`Melody notes` と全候補のスコア（高い順）も表示します。
表示スコアは確率ではありません。ヒステリシスで最高点以外の現コードを保持する場合があります。

実出力ノートも見たい場合は `--debug-accomp` を追加できます。
第二MVPと同様、このオプションは変更拍の和音をルート配置で強調します。
通常の音楽性を評価するときは外してください。

## 最初の演奏テスト

まず120 BPMの一定テンポで、各音を1拍程度ずつ一本指で弾いてください。

```text
C C G G A A G
F F E E D D C
```

1. Melody notesが単音入力の履歴を反映していること。
2. 候補がC / Dm / Em / F / G / Amの範囲に収まること。
3. 変更は拍の境界だけで、少なくとも2拍は同じコードが続くこと。
4. Estimated chordとActive accompaniment chordが一致し、ベース・伴奏が追従すること。
5. 休符でも伴奏が途切れず、無伴奏より伴奏らしく感じられるかを耳で評価すること。

このメロディの唯一の正解進行を保証するテストではありません。
クロマチックなメロディ、別キー、速いテンポや多声音の演奏は今回の評価対象外です。
アプリの拍時計は演奏者のテンポに自動追従しません。

## 構成・テスト

`melody_history.py` が入力履歴、`harmony_estimator.py` が候補採点とコード保持、
`melody_follow.py` が推定結果を既存の伴奏エンジンへ渡す役割です。
推定器はポートやコンピング実装に依存せず、別アルゴリズムに差し替え可能です。
伴奏の拍単位実行部を `Follower.tick_accompaniment` として既存followと共有しています。

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

テストは候補採点、音価と強拍の重み、コード保持・変更しきい値、履歴の上限、
単音入力の即時スルー、次拍のコンピング・ベース送出、既知メロディの候補制限と
変更間隔を確認します。演奏感と聴感は実機で別途評価してください。
